# Artify product roadmap

## North star

Artify should become the most dependable Android drawing environment for Arabic calligraphy and
custom brushes, with professional local creation first and paid cloud collaboration second.

The sequence is deliberate: reliability and stroke quality create trust; coherent UX makes that
quality visible; professional files and cloud services create reasons to pay.

## Prerequisite gate — Repository and Cloud readiness

Before parallel planning or implementation begins:

- Install and verify Git, authenticate GitHub, and create a private repository for the complete app.
- Audit generated files, binaries, extracted references, signing material, and secrets before the
  first commit; then prove the project builds from a clean clone.
- Every Planner/Executor/Reviewer handoff identifies an exact base commit, head commit, branch, and
  clean-worktree state. Codex Cloud can review only content that has been pushed.
- Record owners, dependencies, artifacts, waivers, rollback, and approval status in every spec.

Exit gate: a sanitized default branch builds from a clean clone and is visible to both local Codex
and Codex Cloud without exposing credentials or third-party reference assets.

## Plan 0 — Baseline and measurement

**Purpose:** replace subjective “looks better” decisions with repeatable evidence.

Deliverables:

- Supported-device matrix: small landscape phone, flagship phone, 8–11 inch tablet, stylus device.
- Golden screenshots for gallery, canvas, brush library, layers, colors, and brush studio.
- Macrobenchmarks for launch, frame time, large-canvas navigation, and stroke rendering.
- Crash/data-loss reproduction checklist and an inventory of unfinished or duplicate UI systems.
- A single design token sheet for surfaces, spacing, type, radii, icons, elevation, and motion.
- A reproducible measurement protocol covering device, OS, build, refresh rate, warm-up, run count,
  capture/crop rules, comparison threshold, measurement tool, and pass/fail oracle.
- A severity taxonomy so data loss/security/purchase failures cannot be traded against cosmetic work.

Exit gate: baseline report exists, reference devices are named, and every later phase can compare
against saved metrics rather than opinion.

## Plan 1 — Trust: storage, recovery, and lifecycle

**Purpose:** no paid product can risk the user’s artwork.

Deliverables:

- Atomic project saves with temporary-file replacement and schema versioning.
- Autosave after idle and at lifecycle boundaries without blocking drawing.
- Recovery copy after crash/process death and a visible recovery flow.
- Storage-space checks, corrupt-document quarantine, and actionable error messages.
- Migration tests for every supported project version.
- Transactional consistency across project data, index, metadata, thumbnail, and history.
- Failure injection for full disk, permission loss, reboot/process kill at defined checkpoints,
  interrupted migration, and corrupt or missing assets.

Exit gate: 100 automated save/reopen cycles and forced-kill recovery tests complete without lost or
corrupt artwork; failed saves never overwrite the last valid document.

## Plan 2 — Drawing engine and brush fidelity

**Purpose:** make the stroke itself the product’s strongest feature.

Deliverables:

- Measured stylus event-to-render pipeline, batching, prediction policy, and frame-budget telemetry.
- Stabilization modes (off, streamline, weighted, and end-of-stroke correction) with predictable
  behavior at slow and fast speeds.
- Pressure/tilt/velocity curves with calibration and per-brush overrides.
- Deterministic single-stroke brush previews generated by the same engine used on canvas.
- Brush Studio preview canvas plus size, opacity, spacing, taper, grain, scatter, rotation, wetness,
  and smoothing groups with reset/undo.
- Golden render tests for ink, pencil, paint, spray, texture, stamp, and Arabic broad-edge pens.

Exit gate: no doubled preview strokes; visual previews match canvas output; no visible segmentation
in fast curves; drawing remains within the performance gates in `ACCEPTANCE_CRITERIA.md`.

## Plan 3 — One coherent mobile/tablet UX

**Purpose:** maximize canvas space without making controls hard to reach.

Deliverables:

- Responsive layout rules based on available width/height, not device-name assumptions.
- One floating-panel system for brushes, layers, colors, adjustments, settings, and selection.
- Panels anchored to their triggering controls, dismissible outside, and persistent during
  multi-selection workflows.
- Unified vector icon family; no emoji or one-off AI-looking navigation symbols.
- Correct RTL/LTR alignment, safe areas, transient system bars, and reachable vertical sliders.
- Accessibility semantics and 44–48dp touch targets without visually oversized chrome.

Exit gate: golden screenshots pass at every target size; controls do not overlap or clip; a new user
can create, draw, change brush, add a layer, undo, save, and export without instruction.

## Plan 4 — Arabic brush platform and premium identity

**Purpose:** create a defensible reason to choose Artify rather than a generic drawing app.

Deliverables:

- Curated Arabic families: reed/qalam, Diwani, Thuluth, Ruq’ah, Kufi, manuscript ink, engraving,
  ornament stamps, paper grains, and restoration tools.
- Original monochrome category icons, Arabic naming, authorship/licensing metadata, and consistent
  preview composition.
- Brush-pack format with versioning, import validation, thumbnails, licensing, and sharing.
- In-app creation of personal sets, favorites, recent brushes, search, tags, and reorder.
- Monthly premium-pack pipeline with quality review instead of bulk low-quality presets.

Exit gate: each premium brush has a distinct professional job, a truthful preview, an original or
properly licensed texture, and a human-reviewed sample artwork.

## Plan 5 — Professional document workflow and export

**Purpose:** let users depend on Artify for real client work.

Deliverables:

- Stable large canvases, layer groups, clipping, masks, blend modes, transformations, and history.
- Color profiles and print presets with explicit limitations where full color management is absent.
- Background export queue with progress, cancellation, error recovery, and share-sheet integration.
- Layer-preserving PSD where technically reliable; PNG/JPEG/PDF/TIFF and vector export only for
  content that can be represented faithfully.
- Export compatibility fixtures and round-trip tests.

Exit gate: exported dimensions/colors/layers match fixtures; cancelling export cannot damage the
project; out-of-memory conditions fail safely and explain the remedy.

## Plan 6 — Accounts, sync, and live collaboration

**Purpose:** create the strongest recurring subscription value.

Deliverables:

- Authentication, account deletion, privacy controls, and encrypted transport.
- A data inventory and threat model covering artwork/previews/telemetry, retention, deletion,
  backups, vendors/regions, consent, redaction, least privilege, token rotation, and incidents.
- Project sync with immutable revisions, resumable upload, conflict copies, and offline-first edits.
- Collaboration rooms with presence, invitations, permissions, ordered/idempotent stroke events,
  reconnect, late join, and snapshot recovery.
- A versioned protocol specifying authority, operation IDs, sequence/version rules, snapshots,
  payload/rate limits, authentication, retry/backpressure, persistence, and server migration.
- Regional telemetry for latency and disconnects without collecting artwork content.
- Production hosting that does not sleep; the free Render service remains a development/beta target,
  not a paid-service SLA.

Exit gate: three or more clients converge through duplicate/reordered/dropped messages, simultaneous
same-layer edits, stale clients, offline work, and server restart without missing strokes or silently
replacing a user’s work; tenant-isolation and abuse/load tests pass.

## Plan 7 — Subscription and entitlements

**Purpose:** charge for sustained value without damaging trust.

Free tier:

- Core drawing, essential brushes/layers, local saving, basic image export, and opening owned files.

Pro tier:

- Advanced Brush Studio, larger device-appropriate limits, premium Arabic packs, professional
  exports, and productivity tools.

Cloud/Team tier:

- Sync, revision history, collaboration, shared brush libraries, and team permissions.

Deliverables:

- Google Play Billing, server-side purchase verification, restore-purchase flow, grace period,
  offline entitlement cache, and clear cancellation behavior.
- An account/entitlement identity model designed alongside Plan 6, including refund, clock tamper,
  account merge, reinstall, downgrade, and cross-device restore behavior.
- Feature flags separated from billing so eligibility can be tested safely.
- Paywall shown after value is experienced, with transparent comparisons and no dark patterns.

Exit gate: purchase, renewal, expiry, refund, reinstall, offline grace, and restore scenarios pass;
losing an entitlement never makes local artwork inaccessible.

## Plan 8 — Beta, launch, and growth

**Purpose:** release by evidence, not by feature count.

Deliverables:

- Closed beta with calligraphers, illustrators, students, and Android stylus users.
- Privacy-respecting funnels for first stroke, first save, day-7 return, export, brush creation,
  collaboration success, and trial conversion.
- In-app feedback with diagnostic consent, release notes, support workflow, and incident playbook.
- Store listing based on original Artify value; no competitor trademark dependency.
- Staged rollout with crash/ANR/performance stop conditions.

Exit gate: release metrics meet the thresholds below for two consecutive beta builds and no open
severity-1 data-loss, security, purchase, or collaboration defects remain.

## Recommended sequence

1. Plans 0–1: measure and eliminate data-loss risk.
2. Plans 2–3: make drawing quality and interface visibly professional.
3. Plans 4–5: establish differentiation and professional workflow.
4. Plan 6: harden cloud value after local creation is dependable.
5. Plans 7–8: monetize and launch only after the preceding gates pass.

Plans may overlap only when they do not touch the same source areas. Monetization must not lead the
critical path before reliability, drawing, and recovery gates are complete.

## Executable work breakdown

No item below enters implementation until its own spec is approved:

- **0A–0D:** repository/clean clone; metrics harness; severity and inventory; current brush/theme
  bridge (panel geometry and tone, dropdown arrows, dark-theme logo, coherent icons, persistent
  selection, and the doubled preview-stroke defect).
- **1A–1D:** document transaction model; autosave/lifecycle; recovery/corruption UX; migration and
  failure-injection suite.
- **2A–2E:** input telemetry; sampling/render correctness; smoothing/pressure/tilt; deterministic
  previews; professional Brush Studio.
- **3A–3D:** responsive shell/panels; icon/theme system; RTL/configuration changes; accessibility and
  device states including rotation, font scale, TalkBack, cutouts, multi-window, and foldables.
- **4A–4E:** brush taxonomy and user validation; original/provenance-controlled assets; pack format;
  library/search/sets; premium quality rubric and release cadence.
- **5A–5E:** memory/history model; nondestructive layer features; background raster export; verified
  professional formats; compatibility fixtures.
- **6A–6E:** data/threat model; collaboration protocol; secure identity/sync; live collaboration;
  operational hardening and load/tenant-isolation tests.
- **7A–7D:** entitlement model; purchase lifecycle; honest paywall/feature flags; revenue and support
  operations.
- **8A–8D:** beta cohorts; metric definitions/thresholds; staged rollout; incident and support loop.
