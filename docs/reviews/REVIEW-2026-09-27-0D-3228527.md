### R1: narrow-window geometry (S3)

`PanelGeometry.floatingPlacement` (`ui/common/PanelGeometry.kt:18-43`) now keeps the panel on
screen: the negative-x defect from the brush-library review (H2) is fixed. On a narrow window,
though, it gives up the gutter that kept the tool rail visible before it gives up any panel width:

- At 360 × 640 dp, `safeWidthDp` = min(330, 330, 360 − 32) = **328**. `maxGutter` = 360 − 328 − 16 =
  16, so the gutter is 16 and x = 16. The panel spans 16–344dp, which is **91% of the width**. It
  covers the right-hand sliders, undo/redo and the brush trigger.
- AC1 requires that the panel, the sliders, undo/redo and the triggering control never overlap.
- Scope item 1 requires "at least 40% of the canvas width visible on phones".

`CanvasActivity` is `sensorLandscape` (`AndroidManifest.xml:66`), so this width only occurs in
split-screen, multi-window or freeform windows. Those are still reachable.

The geometry also reads `resources.displayMetrics` (`BrushPanel.kt:95-100`, `PanelUi.kt:490-495`),
not window bounds (`WindowMetrics`) as the technical design specifies. Whether `displayMetrics`
reports the window or the display in multi-window must be confirmed on the device.

The test (`PanelGeometryTest.kt:31`) covers neither 360×640 nor 640×360 from AC1. It also doesn't
cover RTL or any overlap with the rail.

**Required:** verify on the device in split-screen at around 360dp and around 640dp width, in RTL
and LTR. If the rail is covered, keep a minimum gutter equal to the rail's width, shrink the panel
first, and cap it so ≥ 40% of the canvas stays visible. Add the AC1 sizes to the test.

### R2: preview threading does not follow the spec's lifecycle design (S3)

Spec scope item 8 and the technical design say preview jobs run "on `lifecycleScope` of the panel
… one in flight per row, and are cancelled on rebind", with "a neutral placeholder" and a
cross-fade of at most 120ms.

The implementation (`BrushPreviewRenderer.kt:65-82`, `BrushPanel.kt:743-753`) differs in four ways:

1. **Not tied to the panel's lifecycle.** A single-thread executor for the whole process captures
   the `ImageView`. Tasks queued before the panel is dismissed still render afterwards, while the
   artist is drawing again. `AGENTS.md` requires drawing input to stay responsive while previews
   are active, and this has not been measured.
2. **No cancellation for rows detached by an adapter swap.** `stillWanted` checks only the view
   tag, just before the task starts. Every set switch installs a new adapter
   (`BrushPanel.kt:474`). Rows detached by that swap keep their old tag, so their queued renders
   still run.
3. **Errors swallowed.** `runCatching` also swallows `OutOfMemoryError` (`:79`). The row then stays
   blank until it is rebound, and nothing is logged.
4. **No placeholder.** `setImageDrawable(null)` (`:748`) leaves the row empty, not showing the
   neutral placeholder, and there is no cross-fade.

Reading `View.tag` from the preview thread is a benign data race: at worst one extra render.

**Required:** bind jobs to the panel (for example a `CoroutineScope` cancelled in
`onDestroyView`, with a `Job` per holder cancelled on rebind), or record a measured waiver. Show
the placeholder. Treat an OOM as a failed preview that can be retried rather than silently dropped.

### R4: AC3 not met, because emoji are still in the source names (S4, fails AC3)

AC3 says: "No `BrushSet.name` in `BrushLibrary` matches `[\p{So}\p{Sk}]`." All 25 built-in names
still do. They are in `BrushLibrary.kt` at lines 210, 301, 341, 379, 545, 697, 782, 906, 990, 1131,
1216, 1300, 1401, 1525, 1609, 1678, 1747, 1816, 1956, 2064, 2133, 2202, 2325, 2389 and 2450 (for
example `"✏️ الرسم الأولي"`). `R.string.brush_set_my_brushes` also carries one, at
`values/strings.xml:122` (`🖼️ My Brushes`) and `values-ar/strings.xml:54`.

`BrushSetIdentity.displayName` (`BrushLibrary.kt:92-95`) strips them at display time. The rail and
the cover now show the same clean name, and that part is verified. Scope item 3, however, asks for
the names to be cleaned at the source, with the regex kept only as a defensive fallback. The unit
test checks `displayName`, not the names themselves.

Set ids are unchanged, so cleaning the names is a text-only change: nothing is migrated, and no
asset is removed.

**Required:** remove the prefixes from the name strings and from `brush_set_my_brushes` in both
locales. Keep `displayName` as the fallback for imported packs. Add the AC3 assertion over the raw
names. If the owner decides otherwise, record an amended AC3.

### R5: icon set (S4, owner decision)

Scope item 4 asked for an `iconRes` field on `BrushSet`. The implementation uses an explicit map
keyed by id (`BrushLibrary.kt:102-131`). That is acceptable if recorded as a deviation: it is
explicit, and it is tested for every built-in set.

The choices, though, reuse tool glyphs:

- `ic_smudge` for Airbrushing and Spraypaints.
- `ic_urban_grid` (a CAD tool icon) for Square Kufic and Industrial.
- `ic_brush` for 7 sets and `ic_image` for 5.

A set icon identical to a tool icon can read as that tool. E4 ("the icons don't describe their
categories") is only partly resolved. This needs the owner's approval (spec open decision 2). A
dedicated set-icon family is the likely follow-up.

### R6: preview seed identity (S4)

`previewSeed` (`BrushLibrary.kt:141-149`) hashes `id + category + name` with FNV-1a. The design
says the seed comes from the id only. With the name and category included, renaming a brush
(expected when 0A2 replaces third-party names) changes its swatch and invalidates its golden,
although the brush itself did not change. FNV-1a over the id alone keeps the collision benefit.

The seed test (`BrushSetIdentityTest`) compares only two brushes. It should assert that seeds are
unique across the whole library.

### R7: the geometry test duplicates production logic (S4)

`PanelGeometryTest.kt:14-15` rebuilds `BrushPanel.onStart`'s requested width and gutter formula
itself. A later change to `BrushPanel` would not be caught. Extract the brush panel's request (for
example `BrushPanel.requestedPlacement(widthDp)`) and call it from both places.

### R8: scope (S4, process)

The commit adds `gradlew` (248 lines, mode 0755). It looks like the standard wrapper script, but it
is Phase 0A work and outside this handoff's allowed scope. Move it to its own 0A commit, or record
it in the handoff.

### R9: bottom edge on short screens (S4)

At a height of 360dp, `topMarginDp` = 36 and the height clamps to 320 (`BrushPanel.kt:88-92`), so
the panel ends at 356dp, 4dp from the bottom edge. The design rule asks for 16dp. The clamp is new
and bounded. Only the margin is short.

## Verified as meeting the specification

- **Canvas randomness is unchanged.** The canvas engine keeps a clock seed through the default
  argument, and previews pass a fixed seed (`BrushEngine.kt:113-120, 140`;
  `BrushPreviewRenderer.kt:175`).
- **The preview caches are thread-safe.** Every access to both access-ordered caches is locked,
  including reads, and rendering happens outside the lock (`BrushPreviewRenderer.kt:43-57`,
  `BrushTextures.kt:65-68`).
- **No new crash path from `clearCache`.** It has no production caller, so a recycled bitmap cannot
  reach a row.
- **Locking in `getBrushTip` is not in a hot loop.** It is called per stroke or per segment, not
  per stamp, and the lock is uncontended in practice.
- **The view-tag guard is kept**, so a recycled row never shows another brush's bitmap
  (`BrushPanel.kt:723-753`).
- **Touch targets meet 48dp.** Compact rail rows now have a 48dp minimum height with 4dp spacing
  (`:538-541`, `:572`, `:578`). Brush rows were already 54–66dp compact and 84–112dp regular (`:630-634`).
- **The rail and the cover show the same emoji-free name**, and screen readers no longer read the
  pictogram.
- **The negative-x placement is fixed** for every size in the test matrix, on both sides.
- **Other panels still get the edge-safe width.** `PanelUi.dockSheet` now uses the same pure width
  function.
